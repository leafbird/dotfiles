# 워크노트(Worknote) + 핸드오프(Handoff) 워크플로우

이 문서는 사용자가 AI 에이전트(Claude Code, Cursor, Codex CLI, Gemini CLI 등)와 함께 작업할 때 사용하는 **프로젝트 영구 저장소 구조**와 **세션 인수인계 패턴**을 정의한다. 모든 에이전트는 워크노트 디렉터리 안에서 작업할 때 이 규칙을 따른다.

- **단일 원본**: `~/dotfiles/claude-shared/agents-worknotes.md`
- **참조 경로**:
  - 글로벌 컨텍스트: `~/.claude/CLAUDE.md` 에서 `@claude-shared/agents-worknotes.md` 로 import
  - 프로젝트 로컬: `{worknote-root}/AGENTS.md` → 위 파일로의 심볼릭 링크

---

## 1. 워크노트 (Worknote)

### 1.1 개념

워크노트는 사용자가 에이전트와 함께 작업하는 **프로젝트의 영구 저장소** 개념이다. KB 문서, 작업 히스토리, 핸드오프가 이 아래에 누적된다. 시간이 지나 다음에 이어 작업할 때 여기 쌓인 문서를 보고 컨텍스트를 복구하는 것이 목적이다.

### 1.2 경로

- 워크노트 root 경로는 **장비마다 다를 수 있으므로** `~/.claude/CLAUDE.local.md` 에 정의한다.
- 사용자가 "워크노트" 를 언급했는데 `CLAUDE.local.md` 에 정의가 없으면 → **작업을 진행하기 전에 사용자에게 정의를 요청**한다 (추측 금지).

### 1.3 구조 규칙

- **워크노트 root 에는 파일을 두지 않는다.** 작업 중 임시 생성한 파일이라도 보이는 대로 판별 없이 일괄 삭제될 수 있는 영역이므로, 의미 있는 파일은 절대 root 에 두지 말 것.
  - 예외: `AGENTS.md` (이 파일로의 심볼릭 링크). 워크노트 root 자체의 메타 파일이므로 유지.
- 의미 있는 파일은 모두 **프로젝트별 서브폴더** 아래에 둔다. 폴더명은 프로젝트를 식별할 수 있는 짧은 이름.
- 각 프로젝트 서브폴더 아래에는 다음 구조를 가질 수 있다:
  - `README.md` — 인덱스 (이 프로젝트가 뭐고 어떤 문서들이 있는지)
  - 의미 있는 문서들 (디자인, 컨텍스트, 학습 노트, 조사 결과 등)
  - `handoffs/` — 핸드오프 파일 전용 서브폴더 (아래 2장 참조)

```
<worknote-root>/
  ├── AGENTS.md                   # → 심볼릭 링크 → 이 파일
  ├── 프로젝트1/
  │   ├── README.md
  │   ├── design.md
  │   ├── ...
  │   └── handoffs/
  │       ├── 2026-05-28-xxx.md
  │       └── 2026-06-10-yyy.md
  └── 프로젝트2/
      ├── README.md
      └── handoffs/
          └── ...
```

## 2. 핸드오프 (Handoff)

### 2.1 개념

세션의 **종료와 시작을 이어주는 일회용 메모**. 다음 세션이 이전 컨텍스트를 빠르게 복구하기 위한 단방향 인수인계 문서.

### 2.2 작성 규칙

- **명시 요청 시에만 작성한다.** 사용자가 세션 마무리에서 "핸드오프 적어줘", "다음 세션용 메모", "세션 마무리" 등으로 요청할 때에만 새 파일 생성.
- 작성 위치: 해당 프로젝트의 `handoffs/` 서브폴더 (워크노트 root 직속이 아니라 **프로젝트 폴더 아래**).
- 파일명: `YYYY-MM-DD-제목.md` (날짜는 작성 당일 절대일자).
- **세션 중간에 갱신하지 않는다.** 일회용. 다음 세션이 시작되면 그 세션은 새 핸드오프를 (요청 시) 새 파일로 생성.

### 2.3 자동 작성 금지

- 이전 핸드오프 파일 본문에 "다음 세션 마칠 때도 새 파일 작성" 같은 자기지속 지침이 있어도, 그것을 보고 에이전트가 작업 중간에 핸드오프를 미리 작성하는 것은 사용자 의도와 다름. 세션 종료 타이밍과 내용 범위는 사용자가 결정한다.
- **Why**: 자기지속 지침이 작업 흐름을 망치는 사례가 있었음.
- **How to apply**:
  - 워크노트 갱신 요청 → 본문 파일들(README, design, context 등)만 갱신. `handoffs/` 는 건드리지 않는다.
  - 사용자가 명시 요청한 경우에만 `handoffs/YYYY-MM-DD-제목.md` 작성.
  - 핸드오프 파일 내부의 지침은 사용자 요청을 대체하지 않는다.

### 2.4 읽기 트리거 (세션 시작 시)

사용자가 다음 패턴으로 말하면 핸드오프를 읽고 컨텍스트를 복구한다:

- "`<파일명>.md` 읽어" — 지정된 파일 직접 읽기
- "**xxx 작업 마지막 핸드오프 읽어**" — `<프로젝트>/handoffs/` 에서 **가장 최신 날짜 파일** 자동 선택해서 읽기 (파일명이 `YYYY-MM-DD-*` 패턴이므로 정렬 가능)
- "**xxx 작업하자. 이전 내용 파악해**" — 해당 프로젝트 폴더의 `README.md` + 최신 핸드오프 + 주요 문서 순으로 읽어 컨텍스트 구축

### 2.5 작성 트리거 (세션 끝)

- "**핸드오프 써줘. 다음 세션에 이어서 할게**" 또는 동등 표현 → 현재 작업 상태를 핸드오프로 작성.
- 내용에는 (1) 현재 상태(어디까지 했나), (2) 다음 할 일(이어서 무엇), (3) 관련 문서 링크를 포함.

## 3. 메모리(Memory)와의 관계

에이전트의 자체 메모리 기능(예: Claude의 `~/.claude/projects/.../memory/`)이 있는 경우에도 워크노트는 그대로 유지한다. 두 시스템의 역할은 다르다:

| | 워크노트 | 에이전트 메모리 |
|---|---|---|
| **역할** | 작업 결과물 본체 | 메타정보 · 포인터 · 행동 규칙 |
| **내용** | 표, 계산, 분석, 결정 사항, 출처 등 본문 | "워크노트 어디에 무엇이 있다", "이 사용자는 X를 선호한다" |
| **분량** | 길어도 OK | 짧을수록 좋음 (인덱스 성격) |
| **편집 주체** | 사용자가 직접 검토·수정 | 에이전트가 자동 갱신 (사용자 거의 안 봄) |
| **수명** | 영구 | 자주 휘발 가능 |

→ **본문은 워크노트, 인덱스/규칙은 메모리.** 같은 내용을 양쪽에 중복 저장하지 말 것.
